# 测试影响分析

读取目标仓库的本地说明及相关规格、平台规则。先固定分析对象和版本，按用户指定的仓库、提交或分支读取证据。对同名功能或不明确的对比口径，先利用仓库上下文缩小歧义，再确认会改变范围的差异。

- **提交或分支**：记录实际基线和候选 SHA。单提交通常比较父提交到该提交，合并提交确认所需父线。分支改动通常比较 merge-base 到候选，用户指定端点比较时沿用该口径。读取真实差异及必要上下文。默认使用所选提交树，工作区改动仅在明确纳入时分析。遇到子模块或依赖版本变化，按两端锁定版本查差异；对象缺失时记录未知。提交标题和文档变更只能作为线索。
- **功能或需求**：从规格或名称定位可见入口、角色、主链路和状态，再核对调用方、配置、原生宿主、共享组件、接口及现有测试。区分规格期望、候选版本实现和运行证据；按候选树锁定的子模块或依赖版本核对实际代码和入口，文档所述实现依赖未核实时标明。
- 由变更或需求沿调用关系追踪直接影响和必要回归。按实际调用和构建覆盖判断平台。按需检查权限、异常恢复、存量兼容、配置回退和非功能行为。依据不足的预期或端归属写入待确认项。纯文档且已核实没有行为差异时，可给出空的运行回归范围及理由。

保存独立 Markdown，用户未指定文件名时选用可辨识且不覆盖已有产物的名称。包含：

- 分析对象、版本、对比口径和分析边界。
- 影响清单，每项有稳定编号、功能及入口、适用端、直接影响或回归、优先级、需要验证的行为、可定位的依据。
- 有实际判断价值的范围外项及理由。
- 待确认项及其对范围、前置条件或预期的影响。向入口说明是否满足直接继续生成用例的条件及理由。

证据引用保留在此文档。独立调用交付 Markdown；由入口串联时将实际文件路径交给下一步。
